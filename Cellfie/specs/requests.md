# Requests

The requests that shaped Cellfie, oldest first, each with what changed.
The feature files hold the current specification; see the
[index](README.md).

## 2026-10-23

1. **Build a new demo with the same structure as Contact Hub and Mortgage
   Hub: Conway's Game of Life, with the rules as an aityx decision model;
   an infinite board, a random start button, a side panel with the
   requests and responses, and an acceleration control.** Added
   `Cellfie/`: the Flutter app (`cellfie_app`, web, Android, iOS and
   Linux) with the [board](board.md) on a canvas (drag, zoom, tap to draw,
   **Random start**, **Clear**, **Play**, **Step**, **Acceleration** from
   ½ to 8 generations a second or as fast as aityx answers) and the
   [calls panel](calls-panel.md) (every call, what it decided, the request
   and the response as readable JSON with the key parts labeled); a Dart
   API (`cellfie_api`) with `POST /api/step` and `/api/health` that holds
   the aityx key; the Life model (`models/life.json`): Conway's rules as
   a decision table with a why on every row, applied by one aityx call per
   [generation](generation.md) to every distinct situation on the board
   (at most 18), the app counting situations and applying the answer to
   its cells; devbox, process-compose and the health monitor, the
   Makefile, Docker Compose, and the dev container in
   `.devcontainer/Cellfie/`, as Contact Hub has them (see
   [Development environment](dev-environment.md)). Ports 8930 and 8931,
   so it runs alongside the others. The [theme](theme.md) is the aityx
   palette; the [icon](app-icon.md) a glider. The key was copied into
   `Cellfie/.env` from Contact Hub's (git-ignored), to test against the
   live API: `scripts/model-test.sh` runs all 18 situations on aityx.
2. **Also detect patterns, if possible, and notify of them, using aityx;
   check Wikipedia's Game of Life page for the common patterns.** The
   app now also sends every cluster of live cells with its canonical
   shape, and the model's [pattern catalogue](patterns.md), generated by
   `tool/catalogue.dart` from the patterns Wikipedia lists (five still
   lifes, five oscillators, four spaceships, three methuselahs; 37 rows,
   one per phase and size), names each one in the same call, with a
   second table that says what kind it is and describes it. Recognized
   patterns are outlined and named on the board; when a generation has
   more of a pattern than the last, a notice appears over the board and
   in **Patterns noticed** at the top of the panel, with what the pattern
   is. `scripts/model-test.sh` also sends every catalogue shape to aityx.
3. **Let rules be enabled and disabled, Conway's enabled by default, and
   add a couple more rules to make the game more interesting, disabled by
   default.** The request's state now carries `rules`, a switch per rule,
   and each rule's rows in the model's fate table are gated by its
   switch: Conway's (on at the start), HighLife's birth with six
   neighbours (B6, replicators) and Life without death (cells never die),
   both off; a live cell no enabled rule keeps alive dies. **Rules (1 of
   3)** in the controls bar opens a dialog of checkboxes with each rule's
   summary; a change applies from the next generation. See
   [Rules](rules.md).
4. **Rename it: Cellfie.** Life Hub became Cellfie everywhere: the
   folder, `cellfie_app` and `cellfie_api`, the bundle ids
   (`com.aletyx.cellfie_app`), `CELLFIE_BIND_HOST` and `CELLFIE_VERSION`,
   the dev container, the titles and the docs, with the tagline: every
   generation, the cells take a picture of themselves, and aityx says
   who's in it.
5. **Give the player more random start options: dense, sparse, islands
   and so on.** **Random start** is now a menu: Sparse soup, Soup, Dense
   soup, Islands, Glider fleet, Zoo (one of each pattern in the
   catalogue, scattered and turned at random), R-pentomino and Acorn,
   each with a one-line summary. The catalogue's seeds moved from the
   tool into the app (`lib/life/seeds.dart`), so the Zoo and the tool
   share them. See [Board](board.md).
6. **On Patterns noticed, when clicked, go to the call that detected it
   in the panel.** Each notice is a link: tapping it scrolls the panel to
   that generation's call, opens it, and marks it with an amber border.
   See [Calls panel](calls-panel.md).

## 2026-10-27

7. **Make the demos efficient enough for a 4-core codespace: serve a
   release build instead of running the Flutter dev server, and compile
   the API.** `devbox services up` now serves the app's release build
   with a small native web server (`cellfie_api/bin/web_server.dart`:
   `/app/` from `build/web`, `/api/` and `/` proxied to the API, as nginx
   does under Docker Compose) and runs the API compiled with `dart
   compile exe`; both come from `scripts/build.sh`, which builds only
   what changed and runs one Flutter web build at a time across the
   repository. Resident memory drops from about 1.2 GB to about 35 MB,
   and a start after no change takes seconds. Hot reload stays with
   `WEB_MODE=debug` or `devbox run web`. See
   [Development environment](dev-environment.md).

## 2026-10-28

8. **Have the demos prebuilt in the dev container image, ready to boot, and
   push it where anyone can launch it.** Every dev container now runs the
   published image `docker.io/aletyxcode/samples-and-demos-devcontainer`
   (public on Docker Hub, since the organization's GHCR packages can't be
   public), built from `image/Containerfile` with Flutter, process-compose
   and every demo's release web build. A codespace restores the build,
   compiles the API in seconds and starts the services on the image's own
   tools (`DEMOS_TOOLCHAIN=image`, no devbox): every demo answers less than
   four minutes after the request, down from more than ten. See
   [Development environment](dev-environment.md) and `image/README.md`.

## 2026-10-29

9. **Separate the dev containers, images and Codespaces configurations by
   demo group.** Cellfie now opens in the aityx group's dev container,
   **aityx demos** (`.devcontainer/aityx/`), on the group's image
   `docker.io/aletyxcode/samples-and-demos-aityx` (`bash
   image/build-image.sh aityx`), which starts it with the other aityx
   demos and the index page. Its own dev container,
   `.devcontainer/Cellfie/`, was removed. The start-up log is
   `startup.log` at the repository root. The README's codespace link
   points at the group's container. See [Development
   environment](dev-environment.md).

## 2026-10-30

10. **Add a discreet health indicator, top right on every screen, saying
    whether the aityx key is set and aityx is reachable and answering,
    with a tooltip.** The app shows an 8 px dot in the corner: grey while
    checking, green when aityx accepts the API's key, red otherwise, with
    why in its tooltip and for screen readers. The API gained
    `GET /api/aityx`, which checks the key against aityx at most once a
    minute; the app asks it at start and every minute. See [aityx status
    light](aityx-status.md) and the API's spec (since removed: see
    entry 11).

11. **Run the aityx demos entirely in the browser: no per-demo API; the
    app calls aityx itself, on a key the user sets once on the index page,
    with every demo and the index on one origin.** Cellfie's API
    (`cellfie_api/`) is gone. Its Life logic moved into the app
    (`lib/aityx/life.dart`, verbatim, with its tests), the Life model into
    the app's assets (`assets/models/life.json`), and the generations are
    now run by `AityxGenerationStepper`
    (`lib/aityx/generation_stepper.dart`) through the shared package
    `packages/aityx_web`: on the user's key straight to aityx, or, with
    none, the index server's dev key through its proxy; the key never
    shows in the calls panel. The API's checks and wording stay; a
    missing key says `aityx is not set up: set your key on the index
    page.`, with **Set your key**, and aityx's errors say `aityx rejected
    the key`, `aityx did not answer` (`... in time` after the 30 s) or
    `aityx answered HTTP n: <detail>`; an answer of the wrong shape says
    `unexpected answer from aityx`.
    The status light is aityx_web's: it checks the same key, at start, when
    the key changes and on focus (at most every 30 s), and a tap opens the
    index page's key section. The index server serves the release build at
    `/cellfie/` (`--base-href /cellfie/ --no-web-resources-cdn`); the
    per-demo services (process-compose, the health monitor, the web
    server, `scripts/api.sh` and `scripts/flutter-web.sh`), Docker
    Compose and its `docker/` are removed, `scripts/build.sh` builds only
    the web app, and `scripts/model-test.sh` runs the app's
    `aityx`-tagged tests with the key from the root `.env`. See [aityx
    calls](aityx-calls.md), [aityx status light](aityx-status.md) and
    [Development environment](dev-environment.md).

12. **Don't say where the key comes from; check that it works against the
    URL and say that.** The status light's tooltip now reads `aityx: ready — the key works with
    <url>` for any key, the user's or the index server's dev key, and a
    dev key aityx refuses reads `aityx answered HTTP n`; neither names
    `.env` or the environment any more. The index page's key section does
    the same.

13. **Make the Sparse soup sparser and open the board with it, so the
    user only has to press Play.** The Sparse soup's density is now 0.06
    (it was 0.12), and the board opens with one over the cells in view,
    filled once the view has its size. See [Board](board.md).

14. **When a cell dies, mark its place grey for one generation.** The
    board keeps the cells that died in the last generation, as it does
    those born, and paints them grey (`#47474D`) under the live cells;
    the legend adds *died this generation*. See [Board](board.md) and
    [Theme](theme.md).

15. **Make the default speed 1 generation a second.** The Acceleration
    slider starts at 1 generation/s (it was 2), and the label says
    `1 generation/s`, singular. See [Board](board.md).

16. **Zoom with gestures; overlay the zoom and origin buttons on the
    board, as on a map; move the generation count and aityx's response
    time to the side panel; put the controls beside the title, in one
    row; omit the version; drop the label before the acceleration.** The
    controls bar and the status row are gone: the controls sit on the
    right of the title in the app bar (icons with tooltips below 900 px,
    scrolling on a phone), the status is under the calls panel's title
    (over the board's top right when there's no panel), and **Back to the
    origin**, **Zoom in** (+) and **Zoom out** (−) float at the board's
    bottom right. A trackpad pinch in the browser now zooms too (touch
    pinch and the wheel already did). The version and the *Acceleration*
    label (and its icon) are no longer shown; on narrow windows the calls
    button is an icon with the count as a badge. See [Board](board.md)
    and [Calls panel](calls-panel.md).

## 2026-11-03

17. **Separate the demos in games and apps on the index page, then serve
    the index page under /demos and each demo under its own path, such
    as /demos/riverrace, so the demos can be embedded, hidden, in the
    aityx website.** The index page now lists Cellfie under **Games**
    (with RiverRace, PokerFace and RoboRules; Mortgage Hub and Contact
    Hub are **Apps**) and moved from `/` to `/demos/`, and the index
    server serves the release build at `/demos/cellfie/` instead of
    `/cellfie/`: `scripts/build.sh`, `scripts/make.sh` and the Makefile
    build it with `--base-href /demos/cellfie/`, and the dev container
    serves it there too. aityx_web's key page is now `/demos/#aityx-key`
    (the status light and **Set your key** open it), and the dev proxy
    moved from `/aityx/config` and `/aityx/v1/systemone` to
    `/demos/aityx/config` and `/demos/aityx/v1/systemone`. The stepper's
    test now runs on the origin `http://localhost:8800/demos/cellfie/`
    and expects the dev call at `/demos/aityx/v1/systemone`. The docs
    say the new paths. See [aityx calls](aityx-calls.md), [aityx status
    light](aityx-status.md) and [Development
    environment](dev-environment.md).
18. **Remove the running counter from the top bar beside the title, as
    in the other demos: leave the title clear, and in the calls panel,
    before play, show what the demo is and what aityx is doing in it;
    after play, show the calls as they are.** Cellfie's title bar had no
    counter beside the title (the status, `Generation N · M cells ·
    aityx answered in T ms`, sits under the calls panel's header and
    over the board on narrow windows, and stays there), so only the
    panel changed: before the first call it now shows two paragraphs,
    what the demo is (Conway's Game of Life on an infinite board, its
    rules and pattern catalogue as an aityx decision model, the cells
    taking a picture of themselves every generation) and what aityx
    does (one call per generation, with what lives, what dies and the
    patterns coming back, the calls showing as they happen), in the
    same muted centered style, scrolling when the panel is short. Once
    calls arrive the panel shows them as before. See [Calls
    panel](calls-panel.md).

## 2026-11-11

19. **Make the calls panel draggable, to expand it and see the requests;
    add anchors to the key parts of the request and the response, to
    navigate to them directly and precisely.** On wide windows the
    panel's left edge is a handle: drag it to widen the panel (up to all
    but 320 px of the window) or narrow it (to 360 px), double-click it
    for the 440 px it starts at, or use the arrow keys on it. Each JSON
    pane now has a **Jump to** row of chips, one per key part it has
    (more of them: the kinds of pattern, all of what is asked, the kind
    of each cluster and the tokens joined the old ones); a chip, or the
    part's label in the code, scrolls the pane to exactly that value's
    first row, marks the whole value and says above the pane what it is,
    its path and its line. The board is now clipped to its own area, so
    the cells at its edge no longer paint over the handle. See [Calls
    panel](calls-panel.md#width) and [Anchors](calls-panel.md#anchors).
20. **Make the game a bit slower by default: one generation every 3
    seconds.** The Acceleration slider gained a first stop, `1
    generation every 3 s`, and starts there (it started at 1
    generation/s); the other stops are as they were. See
    [Board](board.md#controls).
21. **Make the intro paragraphs on the sidebar a bit shorter and more
    objective, and add a final one, "In memory of John Horton Conway",
    with a link to his Wikipedia page.** The two paragraphs the calls
    panel shows before the first call now say only what the demo is
    (the game, its rules and pattern catalogue as an aityx decision
    model) and what each aityx call sends and gets back; the tagline
    about the cells' picture left the panel (it stays in the README). A
    third line, in italics, reads *In memory of John Horton Conway*,
    his name linking to his Wikipedia page in a new tab, through the new
    dependency `url_launcher`. See [Calls panel](calls-panel.md).
22. **Add the "glider gun" to the list of random starts, and remove from
    that list the number of generations patterns take to settle.**
    **Random start** gained **Glider gun**, Gosper's gun alone in the
    middle of the view, between Zoo and R-pentomino. The R-pentomino's
    and the Acorn's summaries no longer say 1,103 and 5,206
    generations: *Five cells that grow into chaos before they settle*
    and *Seven cells that grow into a vast, long-lived pattern*. See
    [Board](board.md#controls).

## 2026-11-12

23. **Make sure each demo has a link back to "aityx demos"
    (https://aityx.ai/demos), visible but discreet; add it where it is
    missing.** Cellfie had none. The top row gained it under the title: a
    left arrow and *aityx demos*, small and muted, primary and underlined
    under the pointer. A tap opens the index page, `/demos/` on the page's
    origin (https://aityx.ai/demos/ on the aityx website, the local index in
    development), in the same tab; embedded (`?embed=1`) it isn't shown. It
    is `AityxDemosLink`, new in the shared `aityx_web` package. See
    [Board](board.md#the-way-back).
24. **Remove the "Keep it" option from the index page: always keep the
    key.** The index page's key form lost **Remember on this device** /
    **Only this session**: a key is always saved in `localStorage`, on the
    device, until **Forget key**. The limitation about a session-only key
    not reaching a new tab went with it. See [aityx status
    light](aityx-status.md).
25. **In each demo, make sure the key can be set on the index page and
    read in the demo; but when it isn't set there, let the user set it in
    the demo: where the demo already asks for it, or just above the aityx
    call, or on the opening page. With a key set, show nothing at all;
    without one, a small, discreet form with the key and optionally the
    URL, and at the bottom a link to the aityx console to make one.** The
    shared package gained `AityxKeyPrompt`, a form that shows only while
    there is no key (neither the user's nor the index server's dev key)
    and takes no room otherwise: the key, the URL (optional), **Save**,
    and **Get a key in the aityx console**. **Save** checks the key with
    aityx as the index page does and saves only one aityx accepts, in the
    same `localStorage` entries, so the index page and every other demo
    use it too. The life screen shows it under the app bar, above the
    board. The no-key snackbar lost its **Set your key** button, which
    opened the index page: the form is on the screen. A key set on the
    index page is read as before. See [The key form](aityx-key.md).
